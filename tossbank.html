Split Payment 파이프라인 재설계 — 6단계 순차 차감과 보상 트랜잭션

  • 문제: 무상 크레딧 → B2B 크레딧 → 마일리지 → 파트너 포인트 → 신용카드(Nicepay PG) → 포인트 적립 순서로 잔액을 0까지 차감하는 결제 로직이 단일 메서드에 하드코딩되어 있었고, SummaryContext에 단계별 차감 내역을 직접 누적하는 구조여서 결제 수단 추가·순서 변경 시 파이프라인 전체를 수정해야 했습니다. 중간 단계 실패 시 이전 차감 건의 보상 트랜잭션이 없어 부분 결제 상태가 방치되었습니다.
  • 해결: 각 결제 수단을 독립 ChargeStep으로 분리하고 우선순위 기반 Chain of Responsibility로 실행 순서를 제어했습니다. 중간 단계 실패 시 이미 차감된 건을 역순으로 환불하는 Saga 기반 보상 트랜잭션을 구현하고, 단계별 멱등성 키를 부여해 재시도 안전성을 확보했습니다. 정산 집계는 SummaryContext 직접 의존을 제거하고 각 ChargeStep이 발행하는 이벤트를 구독해 건별 집계하는 구조로 분리했습니다.
  • 결과: 결제 수단 추가 시 ChargeStep 구현체 하나만 추가하면 되는 구조로 바꿔 변경 지점을 1곳으로 격리하고, 부분 실패 시 자동 보상으로 미정산 잔류 건을 {N건에서 0건으로} 해소했습니다.
